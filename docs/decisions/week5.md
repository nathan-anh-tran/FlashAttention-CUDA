- Doing softmax: softmax(x_i) = exp(x_i) / sum_j(exp(x_j)), turns a vector into a probability distribution (all values in [0,1], summing to 1)
- Numerical stability: naive softmax overflows for even moderately large inputs (exp(x) overflows float32 for x > ~88). Fix is the subtract-the-max trick: softmax(x_i) = exp(x_i - max(x)) / sum_j(exp(x_j - max(x))). Mathematically an exact identity (multiplying num/denom of a fraction by exp(-max) doesn't change its value), not an approximation — confirmed this isn't "rough," it's provably equal in infinite precision, and in float32 practice it's the more accurate version, not less.

- New pattern learned: reusing shared memory across sequential reduction phases within one kernel. Per-thread values that are needed *after* a reduction (original input value, and the exp'd value) must be saved into local registers before the reduction starts, since the tree-reduction overwrites most threads' sdata slots. Reading a reduction's result back out (e.g. rowMax, rowTotal) needs no special "broadcast" step — every thread can just read sdata[0] directly, since sdata is already block-shared; the reduction loop's last __syncthreads() already guarantees visibility.
